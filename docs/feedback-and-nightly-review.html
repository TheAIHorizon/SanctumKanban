Instructor feedback and nightly AI guidance

This is a live student application. Follow OPERATIONS.md before deployment. Building/pushing this feature does not start a NAS worker or enable any class automatically.

Three distinct places for notes

FeaturePurposeVisibility and authorship
Team NotesCollaborative working notesExisting shared workspace; classmates/observers can view according to class policy. Not private instructor feedback.
Feedback tabInstructor direction, concerns, and required actionsPrivate to current team members and ADMIN instructional staff. Student team leads are not automatically instructional staff.
Saved AI guidancePersisted nightly coaching on a ticketPrivate to current team members and ADMIN staff, clearly labeled AI or fallback. Never presented as instructor-authored or a grade.

Posting instructor feedback

  1. As an ADMIN instructor/GA, open the team's Feedback tab in Detailed or focused team view.
  2. Write a post and choose Guidance, Needs attention, or Action required.
  3. Optionally associate an active ticket from that same team and pin the post. Pinned posts appear above the ordinary chronological feed.
  4. Post it. The author and timestamp are server-supplied. The original message is immutable in this version; clarify or correct it with a follow-up rather than silently rewriting the record.

Team members can reply, acknowledge, and mark posts read. They cannot edit instructor messages, create instructor posts, or change pins—even if their student account has TEAM_LEAD role. Linked active tickets open with the existing edit permissions; inaccessible/archived active-board references get a read-only explanation.

Unread badges are shown only for authorized viewers. Refresh/revisit to see posts from another browser: there is no live-push notification or email service. Acknowledgment is explicit and separate from reading. Replies do not currently count as new unread instructor posts. Archived classes preserve feedback read access but block new posts, replies, acknowledgments, pins, and read-watermark mutations.

Enable nightly reviews for a class

  1. As ADMIN, go to Classes and locate Nightly AI review.
  2. Enable automatic review and select the local hour/time zone. Defaults are 2 a.m., America/Los_Angeles.
  3. Save settings. Enabling the class authorizes automatic processing of saved ticket titles/descriptions by the configured CoyoteGPT service.
  4. Ensure the separate background runner is installed and running. The settings page is not the scheduler process.
  5. Use Queue review now for a saved, enabled configuration when needed. “Queued” means waiting, not completed; watch the last-run summary/error.

Nightly review is off by default for every class. Archived classes cannot be enabled or queued. An admin can disable a class to stop subsequent automatic review; an already-issued model request may finish, but the result is rechecked before it can be saved.

What gets posted

The worker uses the same bounded, grounded Laguna S/DCWF coaching as the manual AI Coach. It saves questions and canonical task suggestions on the ticket without changing its text, status, assignee, dates, or DCWF links. It sends the saved title/description plus relevant reference excerpts—not instructor feedback, comments, or separate student profiles. Avoid putting secrets or unnecessary personal information in ticket text.

  • Open a ticket's AI Coach area and choose Load saved guidance. Authorized readers can also access it from expanded tickets/read-only ticket details.
  • Each review identifies AI versus fallback, the last review time, and whether it matches the current saved draft.
  • Successful reviews of unchanged text/model/prompt version are skipped. Changed content can receive a new review; prior guidance is retained.
  • Request failures or invalid model responses save clearly labeled fallback guidance and may be retried after 24 hours, updating the same content-hash record rather than adding duplicates.
  • No-candidate fallback waits for changed content/model/prompt version. Imported corpus changes alone do not invalidate the current hash; bump the review prompt version deliberately when a framework refresh requires re-review.
  • Workers use a database lease, bounded serial batches, freshness checks, and guarded writes. If a ticket changes during inference, stale advice is not attached to the new draft.

The schedule catches up after a missed local hour while the runner is operating, including a daylight-saving spring-forward gap. It does not promise execution while the NAS/model/worker is offline. Partial batches continue on later worker ticks; the queue is not marked complete until the relevant pass is finished.

Local verification record

The combined local run passed 216 automated tests, 26 HTTP/database scenarios, 8 worker scenarios, and 6 feedback browser scenarios. The worker checks include a real Laguna S saved result, deduplication, a real CLI run, and controlled stale-result/lease tests. Existing Gantt and manual-coach browser regressions also passed. Build, lint, TypeScript, the read-only schema check, a Docker image build/worker dry-run, and targeted independent review passed. Existing unrelated hook warnings remain.

The model can occasionally return an invalid response or fail to respond. Tests exercised the labeled fallback/retry path rather than representing fallback as AI success. The original local Alpha–Echo demo was restored with sample instructor feedback. A local reviewer was started with classes disabled by default; no live NAS changes or activation were performed for this feature.

Operator activation — only after an approved deployment

The source includes an optional Docker Compose nightly profile. The worker uses the same pinned app image and database configuration, has no published port, and does not run schema synchronization itself.

# After backup, rehearsal, reviewed schema/app deployment, and verification:
# Ensure KANBAN_IMAGE identifies the approved image where your Compose uses it.
docker compose --profile nightly up -d --no-deps reviewer

Do not replace NAS-specific Compose/environment settings with this repository's defaults. Review the worker addition as a separate deployment change. The existing app's startup entrypoint can synchronize schema; a worker must only start after that approved schema is present.

# Direct runner, using explicitly supplied approved environment:
NIGHTLY_REVIEW_RUNNER=1 npm run review:nightly -- --once --dry-run
NIGHTLY_REVIEW_RUNNER=1 npm run review:nightly -- --once
NIGHTLY_REVIEW_RUNNER=1 npm run review:nightly -- --daemon

DATABASE_URL must be supplied explicitly by the operator/container environment. AI_BASE_URL, AI_API_KEY, and optionally AI_COACH_MODEL configure inference; the default coaching model is laguna-s. Do not print credentials. Dry-run inspects eligible work without acquiring a lease, calling the model, or saving guidance. The daemon polls every minute and serializes ticks. Review structured counters and sanitized errors, not student text in logs.

Stopping the worker does not remove saved guidance or instructor feedback. Disabling a class does not erase history. No reseeding, database reset, or volume replacement is part of activation.

GA acceptance

  • Instructor post: correct category, author, timestamp, pin and same-team ticket reference.
  • Student: can read/reply/acknowledge but cannot impersonate staff or alter originals.
  • Other-team/classmate and observer: cannot read private feedback or saved guidance, including direct API requests.
  • Archived class: private history readable to authorized viewers; mutations denied.
  • Nightly worker: real model result persists, unchanged input does not duplicate, stale input is skipped, and another worker cannot take an active lease.
  • Admin settings: queue status remains pending during partial work; summaries render safely and reflect only that class.
  • Student ticket content/status/dates/links remain unchanged after AI review.

Local guarded checks: scripts/ga-integration-check.ts, scripts/nightly-review-check.ts, and scripts/feedback-browser-check.mjs. These create disposable fixtures and must never target the live student database.
